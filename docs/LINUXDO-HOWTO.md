# LINUX DO 发帖操作清单

配套正文见 [LINUXDO-POST.md](LINUXDO-POST.md)。

---

## 发帖前：先确认仓库状态

打开 https://github.com/lowseekai/let-deals-radar 确认：

- [ ] README 顶部有 `https://linux.do` 链接
- [ ] 根目录有 `LICENSE`（MIT）
- [ ] 没有二进制文件 / 私有依赖

> 这三项是这个项目满足规则的关键，**已全部就位**。

---

## 第 1 步：准备截图（规则强制）

规则原文：「我帖子内的项目介绍，AI生成、润色内容部分已截图发出」

**需要截 3 张**：

| 截图内容 | 怎么截 |
|---|---|
| **帖子正文** | 在编辑器里粘贴完正文后，截编辑框 |
| **README.md** | 在 GitHub 页面或 VS Code 打开截图 |
| **项目文件结构** | 终端跑 `tree -L 1` 或 GitHub 文件列表截图 |

**要求**：能看出是真实文件，不是编的。带上编辑器界面/时间戳更好。

---

## 第 2 步：发帖

1. 进入 LINUX DO，点「发起讨论」
2. **选标签 `#开源推广`** ← 别忘，这是规则第 1 条
3. 编辑器 toolbar 最右 `+` → **插入模版** → 右侧选 **开源推广发帖模板**
4. 模板会带出 5 项申明，**全部选「是」**
5. 把正文粘在 `---` 分隔线之后
6. 上传 3 张截图
7. 发布

---

## 第 3 步：发帖后

| 要做 | 说明 |
|---|---|
| **及时回帖** | 有人提问就答，社区看的是长期表现 |
| **处理 issue** | 有人反馈就去改，改完在帖子里同步 |
| ❌ **别放 QQ/TG 群** | 社区反感引流，公益推广规则明确禁止 |

---

## 常见拒稿原因与对策

| 原因 | 对策 |
|---|---|
| 没打 `#开源推广` 标签 | 补上重新发 |
| README 没有 linux.do 链接 | 已有，确认 commit 已推送 |
| 缺 AI 内容截图 | 补齐 3 张 |
| 被判定非「完整开源」 | 检查是否夹带二进制/私有依赖 |

## 关于「AI 生成内容」这一项

**如实截图即可。** 这个项目的代码和文档确实是 AI 协作产出的，这是事实。

规则要的是**透明**，不是禁止 AI。试图含糊过去，被佬友发现反而更难堪。
