# VPS 优惠雷达：把 LowEndTalk 的优惠汇总成一张中文表

## 起因

混 VPS 圈的人大概都有这个体验：想知道最近有什么便宜机器，得同时刷
LowEndTalk 的 Offers 版和 LowEndBox，帖子是英文的，价格规格散落在正文里，
而且**最关键的库存信息根本不在正文**——商家只在回帖里说「售罄了」。

我就想做个东西，把这事自动化。

## 它做什么

抓取 LET / LEB 的 RSS → 抽取结构化字段 → 生成一个可筛选的静态站。

核心不是「搬内容」，而是**抽取**：

- 规格（8C / 32G / 300G NVMe / 25TB）
- 价格（€129/年，自动归一化跨币种）
- 折扣力度、循环折扣、优惠码
- **库存状态**——这是重点

## 最难的部分：库存

商家不主动汇报库存。帖子正文通常只有「XX 优惠，$29/年」，
而真实的「已售罄」藏在第 45 楼的商家回复里。

所以我做了**回帖抓取层**，而且发现一个反直觉的规律：

> 商家表态集中在回帖流的 **75%–100%** 位置——他们只在被问到时才回。

因此策略是**从最后一页往前抓**，而不是从头翻。只抓 1 页就能拿到最新状态。

效果：库存判定率从 25%（只看正文）提到 31%，虽然仍然不高，
但每一条判定都有**原文证据**可核对。

## 另一个坑：表格重建

RSS 会把 HTML 表格拍平，每行只剩一串裸值：

```
Anniversary XXL
8
32 GB
300 GB
25 TB
€129
```

没有列名。只能**按顺序推断**：第 1 个 GB = 内存，第 2 个 = 存储，TB = 流量。

这段逻辑踩了不少坑，现在有专门的测试锁着（`test_textutil.py`）。

## 工程上的取舍

**零运行时依赖**——只用 Python 标准库。理由是这东西要长期跑在
GitHub Actions 上，少一个依赖少一个坏掉的理由。

**GitHub Actions 抓取而不是自己服务器**——LET 前面有 Cloudflare，
云主机固定 IP 容易被拦。Actions 每次不同 IP，天然规避。

**124 → 235 个测试**——每次改抽取规则都可能引入回归，测试是唯一保险。

## 一些诚实的局限

- **库存判定率只有 31%**，69% 是「待确认」。这是真实边界，商家就是不说。
- **只有 3% 的帖子能解析出完整套餐表**，多数帖子正文是自由格式。
- **CPU 型号覆盖率 42%**，多数帖子不写型号。
- **正则面向英文帖**，中文帖未优化。

「待确认」不等于有货——这点我在页面上明确写了。

## 技术栈

Python 3.10+ / 纯标准库 / GitHub Actions / 静态站
